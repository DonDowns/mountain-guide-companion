# Pages verifier browser operations

The Companion Pages verifier renders deployed `index.html` in Chromium with JavaScript disabled and checks both candidate.6 disclosures. “Test version” and “Physical phone testing is still required. This is not yet a field release.” must each occur exactly once in their intended element and be assembled from perceptible descendant text runs. The check covers semantic hiding, cumulative opacity, clipping, transforms, character-level range geometry, and usable-viewport intersection. Scrolling is forced to instant behavior. Each disclosure's scroll, frame waits, and geometry samples share one deadline and must stabilize.

## Immutable response evidence

Each attempt acquires two bounded observations of every required deployment resource. Both observations must have the same canonical final URL, strictly parsed delivered `Content-Type`, byte count, and SHA-256. A mismatch fails the attempt before navigation. The first confirmed observation becomes the attempt's immutable response snapshot. Preflight inspection, stylesheet parsing, nested-document parsing, Chromium route fulfillment, and final bundle accounting all use that same snapshot; they never reload a resource to replace bytes already accepted or rendered. Immediately before every fulfillment the stored byte count and SHA-256 are recomputed, so in-memory mutation also fails closed.

The locked offline bundle supplies the required byte count and SHA-256. A snapshot must match both before Chromium starts. Changing-response loaders for stylesheets, images, and nested documents are rejected on their second bounded observation, including the canonical/substituted/canonical sequence that previously allowed a late canonical load to repair altered rendered bytes. Redirect identity, final URL, delivered MIME, bytes, byte count, and SHA-256 therefore belong to one evidence record.

## Authored-source identity and browser coalescing

Before DOM normalization, a bounded source-preserving lexer validates root HTML, HTML/XHTML/XML/SVG nested documents, every `srcdoc`, and all recursively nested `template.content`. Production lexical mode comes only from the immutable response snapshot's already validated delivered media type and approved path policy; `srcdoc` is the one browser-defined `text/html` mode. A filename guess cannot select a more permissive grammar.

The `text/html` lexer has explicit data, comment, canonical-doctype, script-data, RAWTEXT, and RCDATA handling. RCDATA covers `title` and `textarea`; RAWTEXT covers `style`, `xmp`, `iframe`, `noembed`, and `noframes`; script uses a separate script-data policy. `noscript` remains data because both verifier parsing contexts have scripting disabled, and the DOM/source pairing proves that state. Every root HTML document, nested `text/html` document, and `srcdoc` must begin with the canonical HTML doctype and must author exactly one `html` root whose direct element children are `head` followed by `body`. A pre-doctype comment is not an accepted prolog. Start and end tags must be explicitly balanced in the accepted subset. The lexer finds the earliest browser-applicable special-text end-tag candidate, including whitespace and slash delimiters Chromium recognizes, and rejects noncanonical candidate syntax instead of scanning onward to a later convenient close. Script escape-state syntax is unsupported and fails closed. Plaintext state is explicitly unsupported. Ordinary comments retain the audited strict subset: malformed or abruptly closed comments, `<!-->`/`--!>` breakouts, nested or repeated comment openers, bogus declarations, CDATA-like syntax, and processing-instruction-like syntax fail closed.

Every accepted start tag becomes a source token with its ordinal, authored tag spelling, each authored attribute spelling, quote form, explicit-value state, raw value, and character-reference evidence. Same-case or case-varied HTML duplicate attributes fail while both source occurrences are still observable. Nulls, unsupported controls, malformed or unterminated tags/quotes, ambiguous unquoted syntax, and normalization-dependent HTML attribute references also fail. `srcdoc` permits only the five structural named references needed to quote nested markup; it is decoded exactly one level and checked again as `text/html`, so an encoded inner alias or tokenizer breakout remains visible to policy.

After lexical acceptance, a detached Chromium `DOMParser` must reproduce the authored element tree, not merely the same flattened element inventory. Every element token carries its exact parent ordinal, element-child index, and recursive structural path, including the template-content boundary. DOM element name, parent, child position, structural path, attribute count, qualified attribute spelling, and proved value must all agree. Parser-created, merged, foster-parented, reconstructed, or ignored-token-compensated structures therefore fail rather than acquiring authorization without an authored token. The proved element path and namespace URI/local-name identity, token ordinal, raw attribute value, and character-reference evidence flow into each entry in the structured ledger. Each eligible entry also records active/inactive and template status, document-instance key, owner path and base, element namespace/local name, attribute namespace/local name, literal value, occurrence, fetch semantics, and resolved allowlisted destination. External and `srcdoc` document instances receive distinct ancestry keys even when they have the same URL. The root is document 1; at most 64 documents may be inspected, nesting may extend at most 8 levels below the root, template recursion has the same depth and count bounds, and an ancestry cycle is rejected. Template content is inspected with the ordinary navigation, CSP, SRI, stylesheet, HTML, SVG, XML, and URL-attribute rules, but any fetching reference remains inert and cannot authorize a browser route.

Network events are transport evidence, not reference consumption by themselves. Chromium exposes the requesting document path, fetch kind, and destination, so one transport event may be shared only among active entries with those three values. A transport group must route at least once, may route no more times than its authored occurrences, must finish every routed request, and may have no failed request. This admits legitimate request coalescing and separate requests for repeated document instances while rejecting unexplained over-consumption. Browser redirects and retries are not needed under the verifier's deterministic intercepted `200` fulfillment and therefore receive no extra allowance; deployment redirects must resolve to the identical approved path, and retry attempts receive fresh response snapshots. Transport never supplies application proof. Entries remain separate application identities by document instance, exact authored element path or processing-instruction ordinal, element namespace/local name, attribute namespace/local name, literal, and fetch semantics. Different literals that normalize to one instance/kind/destination are rejected. After `load`, the verifier reconstructs the same structural path in every document instance and requires exactly one successful DOM application record for every eligible authored-policy entry; external frames and `srcdoc` applications also bind recursion to that exact authored iframe. Thus one coalesced request is accepted only when every matching image decoded visibly, every stylesheet was applied with readable CSSOM, and every nested document remained accessible and finished. An unsupported foreign element, hidden, inactive, invalid, detached, template, non-fetching, or unrelated occurrence cannot lend authorization or application proof.

Browser `requestfailed` is fatal. Each active transport group must be routed and reach `requestfinished`; preflight bytes alone are insufficient. Null or inaccessible `contentDocument`, an unexpected browser-applied resource, a missing occurrence, a duplicate application record, a wrong applied destination, or a failed decode/application stops verification.

## Supported resource forms

The deliberately narrow active set is:

- ordinary, enabled, non-alternate `screen`/`all` `.css` stylesheet links, with no SRI and no CSS `@import` or `url()` dependency;
- visible eager/default HTML `img[src]` references to delivered `image/svg+xml` resources, with successful completion, nonzero natural dimensions, and proved usable geometry;
- visible, non-lazy, unsandboxed HTML `iframe` documents using allowlisted relative `.html`, `.htm`, `.xhtml`, `.xml`, or `.svg` paths, when `contentDocument` stays accessible, usable iframe geometry is proved, and all descendant references can be proved;
- visible unsandboxed `iframe[srcdoc]` documents under the same complete recursive inspection; and
- XML `<?xml-stylesheet?>` only for an active `text/css` `screen`/`all` stylesheet with no integrity metadata and only the documented PI attributes.

Inline SVG without external URL-bearing constructs is inert and allowed. The complete supported external visual-resource list is therefore a visible eager HTML `img[src]` whose allowlisted resource is SVG. Raster aliases do not have an approved delivered-MIME policy in this verifier package.

For each supported image and iframe occurrence, deterministic inspection first rejects hidden state, computed content width or height below one pixel, clipping, effectively zero transform scale, transform translation or initial placement beyond the bounded inspection distance, and zero-size overflow ancestors. Legitimate below-fold content within the 16,384-pixel/eight-viewport inspection bound is instant-scrolled into view. The final border geometry and clipping-chain intersection must overlap the usable viewport by at least one pixel in each dimension. Generalized pixel-level occlusion by unrelated opaque overlays remains outside this verifier.

Local manifest and icon links are validated as inactive metadata. Navigation/SEO metadata relationships such as canonical, author, help, license, next, `prev`, search, and tag remain non-fetching and cannot authorize a route. Local script sources are validated as inactive because JavaScript is disabled; their delivered MIME and bytes are still checked by the bundle integrity pass.

## Rejected resource and document forms

Deterministic application proof is not claimed for the following, so they fail before navigation: every declarative-shadow mode (including open, closed, and invalid modes), fetching references inside inert templates after complete recursive inspection, imperative shadow roots, legacy `frame`, sandboxed external or `srcdoc` iframes, an iframe carrying both `src` and `srcdoc`, object/embed content, image inputs, video posters, legacy HTML `background`, lazy images or iframes, media sources, portals, `srcset`/`imagesrcset`, and unknown URL-bearing HTML attributes.

All SVG URL-bearing forms are rejected before Chromium can classify or coalesce them, including local-fragment and external references. This includes `image`, `use`, `feImage`, script or anchor `href`/`xlink:href`, and `url()` in `fill`, `stroke`, `mask`, `clip-path`, `filter`, `marker`, `marker-start`, `marker-mid`, `marker-end`, `cursor`, or any other presentation attribute. No SVG request kind or application behavior is claimed as supported.

Other fail-closed forms include all SRI-bearing resource constructs; CSP in authored metadata or verifier-loaded response headers; preload, prefetch, preconnect, modulepreload, DNS-prefetch, and prerender; unknown link relationships; disabled, alternate, print-only, or unknown-media stylesheets; application-cache manifests; `<base>`; refresh navigation; object codebases; and malformed HTML/XML resource syntax.

## Navigation, path, encoding, and XML policy

Navigation controls are inspected separately and never enter an active resource group. Candidate.6 has exactly four approved non-fetching navigation literals: `#app-main`, `#companion-home`, `https://mountainguide.vondadowns.com/`, and `tel:911`. Other anchor/area destinations and every authored `form[action]`, `formaction`, `ping`, `cite`, `longdesc`, `lowsrc`, `dynsrc`, `datasrc`, `itemid`, `profile`, or `usemap` are rejected. This bounded exception preserves the locked candidate.6 HTML while rejecting root-relative, scheme-relative, other absolute, query-bearing, other fragment-bearing, traversal, backslash, encoded, repeated-encoded, or ambiguous navigation destinations in root, template, nested-document, and `srcdoc` placements.

Active resource literals must be nonempty deployment-relative paths using either `name` or `./name` syntax. Root-relative, absolute, scheme-relative, query, fragment, empty-segment, dot-segment, traversal, or backslash forms fail before URL normalization. Percent encoding is not needed by candidate.6 and is rejected in all authored active resource literals, including partially encoded aliases, mixed-case encodings, encoded separators, and repeated encoding.

XML-family media types use strict XML tokenization and never inherit HTML script, RAWTEXT, or RCDATA behavior: child elements inside XHTML/XML/SVG `script` or `style` remain ordinary namespace-aware elements and receive the same provenance and URL-policy inspection. Start/end tags are case-sensitive and balanced; attribute values are quoted; XML comments, CDATA sections, declarations, and processing instructions require their exact XML terminators. Document types, internal subsets, and entity declarations are unsupported because complete expansion provenance is not available. Only the five predefined XML entities are accepted and decoded while their raw attribute evidence is retained; numeric, custom, partial, and unknown entity references fail.

XML parsing also rejects malformed documents, XInclude, unknown URL-bearing XML elements/attributes, and unknown external inclusion forms. Attribute policy is classified from the DOM namespace URI and local name, never from one literal prefix or qualified spelling. The same rule runs for `text/html`, `application/xhtml+xml`, `application/xml`, `text/xml`, and `image/svg+xml`. Namespace declarations are inert; URL/resource, navigation, inclusion, schema-location, XML Base, SVG base-control, and MathML URL-like attributes in any other unsupported element or attribute namespace fail closed. Unknown foreign attributes also fail when their value has URL/location syntax, so changing an arbitrary prefix cannot change the decision. SVG `href` is rejected for every prefix that resolves to the same namespace, including arbitrary aliases of XLink. Committed production-path rejection tests require zero browser navigation, zero intercepted route invocation, and zero controlled target-resource reads. Every DOM processing instruction must pair one-to-one with its preserved authored instruction token. The target allowlist contains only the XML declaration handled by the parser and the narrowly parsed `xml-stylesheet` target. Every other PI target is rejected regardless of whether its payload is quoted, unquoted, whitespace-only, filename-like, host-like, relative, root-relative, encoded, dotted, or adjacent. XML stylesheet PIs require a quoted local `href`, explicit `type="text/css"`, supported `screen`/`all` media, and no unknown attributes; they reject alternate activation, malformed attributes, unsupported additions, and both malformed and syntactically valid SRI/integrity values.

## Delivered MIME and byte integrity

Every required loader response must deliver a `Content-Type`; absence or an empty value is an error. A strict HTTP media-type parser requires token/token syntax, semicolon-delimited `name=value` parameters, terminated quoted strings and escapes, and no controls, malformed separators, bare parameters, or comma-joined values. Valid quoted/unquoted parameters, legal whitespace, and case variations are accepted. Header names are case-insensitive. Identical duplicate field values are accepted when the loader preserves them as separate values; conflicting duplicates are rejected. A Fetch `Headers` object exposes joined duplicates as one comma-joined value, which is rejected because original field identity can no longer be proved.

The accepted families are exact after strict case-insensitive parsing: HTML `text/html`, XHTML `application/xhtml+xml`, XML `application/xml` or `text/xml`, CSS `text/css`, JavaScript `text/javascript` or `application/javascript`, JSON `application/json`, web manifest `application/manifest+json` or `application/json`, SVG `image/svg+xml`, PDF `application/pdf`, and PNG `image/png`. Wrong types and extensions without a declared policy fail.

The exact validated delivered header from the immutable snapshot is preserved in Chromium route fulfillment. The verifier never replaces missing or invalid delivered MIME with a pathname-derived value. Origin, deployment base, allowlist membership, redirect identity, response policy, MIME, resource byte count, and SHA-256 are recorded and compared as one response identity.

## Bounded lifecycle and exclusions

Every metadata, HTML, render-resource, redirect, identity, post-render integrity load, DOM evaluation, geometry evaluation, and inter-frame wait is bounded. The default fetch loader uses an abort signal; injected loaders are bounded and late settlements are consumed. Browser, context, page, and cleanup ownership is retained across timeout and failure. Late acquisition or cleanup errors remain secondary diagnostics without masking the primary failure. Retry counts and delays accept canonical safe unsigned decimal syntax only.

Aggregate hidden text, generalized pixel-occlusion analysis, screenshots, and physical-device validation are outside this bounded verifier. Source-preserving validation deliberately accepts only the documented deterministic HTML and XML lexical subsets; any future syntax whose browser state, element provenance, attribute provenance, or entity expansion cannot be proved fails closed. Automated rendering does not replace physical iPhone, offline cold-launch, readability, touch, print, waterproofing, communication-path, or second-person usability checks.

Pull-request CI runs inside `mcr.microsoft.com/playwright:v1.62.1-noble`. The image, `package.json`, lockfile, installed package, and local CLI versions must match. Pages uses `npm ci`, verifies the local package/CLI, and installs Chromium with `npx --no-install playwright install --with-deps chromium`; any mismatch or installation failure stops before deployment verification.

`npm run test:live-verifier` is deterministic and local-only. It uses reserved `.invalid` origins, intercepted Chromium routes, controlled fixtures, and injected failures; it never probes the public Companion site. `npm run check:live` is separate and may run only in the authorized post-deployment Pages workflow.
